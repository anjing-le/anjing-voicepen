# VoicePen 项目章程

## 1. 产品使命

VoicePen（声笔）是一款面向 macOS 与 Windows 的轻量 AI 语音转文字助手。它让用户通过全局快捷键完成“录音 → 转写 → 润色 → 复制 / 可选粘贴”，以尽可能低的打扰提升日常文字输入效率。

本项目自用优先、开放使用：我们基于真实需求持续迭代；正式发布后，其他人可通过 GitHub Releases 获取应用，并通过 Issue 或 Pull Request 参与改进。

## 2. 长期产品原则

- **轻量单一职责**：围绕语音输入闭环演进，不扩张为聊天助手、桌宠、知识库或复杂工作台。
- **双端一等支持**：macOS 与 Windows 都是正式产品平台；“能够编译”不等于“平台已验收”。
- **用户自带服务**：用户自行配置 STT 与 LLM 的地址、API Key 和模型（BYOK）；项目不建设账号、计费或自有 AI 中转服务。
- **本地优先**：配置与输入流程尽可能停留在本机；除用户配置的 AI 服务和 GitHub 更新源外，不引入额外云依赖。
- **更新由用户决定**：应用可以发现 GitHub Releases 中的新版本并展示更新要点，但只有用户确认后才下载安装。
- **安全发布**：应用更新必须验证签名。真实 API Key、代码签名证书、更新私钥不得进入仓库。
- **克制演进**：只有一个正式更新通道，不预建 beta、nightly、多租户、云同步等尚无真实需求的系统。

## 3. 用户体验基线

1. 用户从 GitHub Releases 下载适合其系统的安装包。
2. 首次使用时填写 STT、LLM、润色提示词、全局快捷键等本地配置。
3. 按一次快捷键开始录音，再按一次停止。
4. 应用依次完成转写、润色和剪贴板写入；开启自动粘贴时再尝试输入当前文本框。
5. API、网络、权限或粘贴失败时提供可理解且可恢复的反馈，不应让应用进入不可继续使用的状态。
6. 新版本可用时展示当前版本、新版本、更新要点及可获得的包信息；用户可以稍后处理或确认更新。
7. 取消、下载失败或签名验证失败不得妨碍当前版本继续运行。

## 4. 范围边界

下表是批准的**目标支持矩阵**，不是当前 `0.1.0` 已交付能力。达到正式支持状态必须满足表内证据；当前真实设备和 OTA 验收仍未完成。

### 正式支持

| 平台 | 架构 | 产品地位 | 发布目标 | 验收要求 |
| --- | --- | --- | --- | --- |
| macOS | Apple Silicon (`aarch64`) | 正式支持 | 签名、公证的安装包与更新产物 | 真实设备完成安装、权限、录音、快捷键、粘贴、更新 |
| macOS | Intel (`x86_64`) | 正式支持 | 签名、公证的安装包与更新产物 | 对应环境或可信等效环境完成完整验证 |
| Windows | x64 | 正式支持 | 代码签名的安装包与更新产物 | 真实系统完成安装、权限、录音、快捷键、粘贴、更新 |

Linux 兼容代码可保留，但现阶段不构成发布承诺或验收门禁。Windows ARM、移动端、Mac App Store 与 Microsoft Store 不在当前范围。

### 明确排除

- 强制更新或未经确认的静默安装
- 多更新通道
- 用户账号、云同步、数据库及管理后台
- 官方托管 AI 服务或代理用户密钥
- 聊天、知识库、桌宠及复杂工作台
- 在没有真实平台证据时宣称支持该平台

## 5. 必须保留的现有能力

- 本地配置与 BYOK
- 全局快捷键控制录音
- STT 转写与 LLM 润色
- 结果复制到剪贴板及可选自动粘贴
- 状态浮窗、设置窗口、系统托盘
- `light`、`dark`、`system` 主题

行为重构必须提供等价验证或明确的产品决策，不得因内部拆分无意移除这些能力。

## 6. 工程治理

- 开发直接发生在 `main`，每个批准阶段形成独立、可解释的 commit，并在验证通过后 push 到 `origin/main`。
- 阶段提交前必须检查工作区和 diff，确认没有混入密钥、构建产物或无关变更。
- 阶段验证失败时不得 push；修复并重新完成门禁后再提交。
- 正式 GitHub Release、安装包发布及任何付费签名操作需要单独确认，不因日常 push 授权而自动获得授权。
- 不覆盖或重置用户及其他协作者的未提交更改。

## 7. 完成度定义

项目报告必须区分：

- **代码完成**：实现和静态检查完成。
- **本地验收完成**：当前开发环境的自动测试及人工检查完成。
- **生产环境验收完成**：目标系统的签名安装、真实权限、设备流程和跨版本更新均有证据。

只有代码完成时，不得表述为双端正式发布完成。
