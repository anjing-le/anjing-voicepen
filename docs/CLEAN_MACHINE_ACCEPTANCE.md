# VoicePen 干净电脑验收手册

本手册用于在未参与开发、未安装开发工具的电脑上验证正式 GitHub Release。它验证的是用户实际拿到的发布产物，不以开发版、CI 成功或本机源码构建代替。macOS 产物采用 ad-hoc code seal 且未经 Apple 公证；Updater 仍使用独立签名。

## 1. 验收目标与版本安排

一次完整验收至少需要两个正式版本：

- **基线版本 A**：从 GitHub Releases 手工下载并完成干净安装。
- **升级版本 B**：版本号高于 A，由 A 在应用内发现，用于验证 OTA。

首个 Release 只能完成安装和核心功能基线；在更高版本发布并从旧版成功升级前，不得把 OTA 标记为通过。Draft Release 不会被正式更新端点发现，OTA 必须使用已发布且签名有效的 Release。

## 2. 测试前准备

为每台电脑建立一份验收记录，并先记录：

- 测试日期、执行人、设备类型。
- OS 完整版本与 CPU 架构。
- VoicePen 版本、Git tag、对应 commit SHA、Release URL 和安装资产文件名。
- 是否为新系统账户；是否曾安装 VoicePen；如曾安装，需说明如何隔离旧配置。
- STT/LLM 服务类型与模型名。API Key 只在应用设置中输入，任何截图、日志或报告都不得包含 Key。

建议准备一个普通权限文本编辑器和一个浏览器输入框作为粘贴目标。测试电脑不需要 Node.js、Rust、Git 或源码。

## 3. 下载、校验与安装

1. 只从 `https://github.com/anjing-le/anjing-voicepen/releases` 进入对应 Release。
2. 确认 Release 不是 Draft 或 prerelease，版本与更新说明符合预期。
3. 下载与系统匹配的**安装资产**；不要使用聊天附件、网盘转存或来源不明的镜像：
   - macOS Apple Silicon 选择文件名标识 `aarch64` 的 `.dmg`，Intel 选择标识 `x64` 或 `x86_64` 的 `.dmg`。
   - Windows x64 选择明确标识 x64 的 NSIS `setup.exe` 或 `.msi` 安装器；同一轮验收记录实际选择的格式。
   - `.app.tar.gz`、`.sig` 和 `latest.json` 是 OTA/校验资产，不供用户手工安装。文件名或架构无法明确对应时停止并向项目维护者确认。
4. macOS 首次双击预期会被 Gatekeeper 阻止，因为项目明确不做 Apple 公证。确认来源后，使用 Finder 和“系统设置 → 隐私与安全性 → 仍要打开”的系统界面放行。不得关闭 Gatekeeper、执行 `xattr`、使用 `sudo` 或自动清除 quarantine；记录实际提示，并明确 Apple 未验证开发者或完成恶意软件公证检查。
5. Windows 检查安装器数字签名与发布者，记录 SmartScreen 的实际表现；未知或无效发布者视为失败，不建议用户绕过。
6. 记录安装结果和必要的脱敏截图。下载来源或资产架构不符时立即停止；macOS 的“未验证开发者”本身是已知分发模式，不误判为 Developer ID 签名失败。

## 4. 首次启动与本地配置

逐项验证并记录 `通过`、`失败` 或 `阻塞`：

- 浮窗出现，设置页可打开、隐藏并从托盘重新打开。
- 首次麦克风授权的主体名称正确；分别记录允许或拒绝后的反馈与恢复路径。
- 填写 STT/LLM Base URL、Key、Model、润色 Prompt、快捷键、主题和自动粘贴选项。
- 运行应用内诊断；报告只保留状态和脱敏错误，不复制 Key、Authorization header 或服务响应正文。
- 退出并重新启动，确认非敏感设置保留且应用仍可工作。

## 5. 核心语音闭环

至少完成以下场景：

1. 在普通文本编辑器聚焦输入框，按快捷键开始录音，再按一次停止。
2. 确认状态依次进入录音、转写、润色和完成，没有并发重复任务。
3. 确认结果进入剪贴板；开启自动粘贴时确认结果进入原输入框。
4. 关闭自动粘贴重复测试，确认只写入剪贴板。
5. 快速连按快捷键、处理期间再次按键，并验证应用没有崩溃或用旧任务覆盖新结果。
6. 拒绝/撤销麦克风权限、断网、临时填写一个明确无效的**非秘密字段**（例如测试模型名），确认错误可理解且恢复后可继续使用。先记住原非秘密值，测试后由用户在 UI 中恢复；不得导出、复制或展示含 Key 的配置文件。
7. 测试快捷键冲突、睡眠/锁屏恢复、应用隐藏/唤醒及托盘退出。

macOS 额外验证辅助功能/自动化授权在允许、拒绝和撤销后的自动粘贴表现。Windows 额外验证记事本、浏览器和一个高权限边界场景；自动粘贴失败时，结果仍必须留在剪贴板。

## 6. OTA 验收（版本 A → B）

开始前确认电脑运行基线版本 A，且已保存一组可识别的非秘密设置。

1. **无更新**：在 B 尚未发布时检查更新，确认没有误报。
2. **发现更新**：发布 B 后重新检查，确认显示当前版本、目标版本和与 Release 一致的更新要点。
3. **稍后更新**：选择稍后，确认应用不下载或安装，A 仍能完成语音闭环。
4. **确认更新**：再次检查并确认更新，记录下载、Updater 签名验证、安装/重启过程；不得要求用户关闭系统安全验证。
5. **升级结果**：记录 B 启动时是否再次被 Gatekeeper 拦截；如发生，只能沿用系统 UI 的“仍要打开”路径。确认版本为 B、原有配置保留，并复核麦克风/辅助功能是否需要重新授权，再执行一次完整语音闭环。
6. **网络失败**：在隔离测试中中断网络，确认更新失败不会损坏 A，恢复网络后可重试。
7. **恢复能力**：记录安装失败或应用重启失败时的实际提示与恢复步骤。签名错误测试应使用专门的隔离演练产物或自动化测试，不从公开 Release 分发恶意篡改包。

应用只跟随一个正式通道。不要使用 beta、nightly 或 prerelease 来代替上述路径，也不要原地替换同一 Release 的资产。

## 7. 卸载与数据边界

- 从系统正常卸载 VoicePen，确认后台进程、托盘和快捷键不再存在。
- 记录本地配置是否保留；不要在报告中上传配置文件，因为其中可能含 API Key。
- 如需彻底清理后复测，只删除已确认属于 VoicePen 的配置，并在记录中注明；不要执行宽泛目录删除。
